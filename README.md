# Aura AI

A private, multilingual AI mental-wellness companion — empathetic chat, live-synthesized soundscapes, a guided breathing coach, and a local mood-analytics dashboard. 100% in-browser: no accounts, no backend calls, all data in `localStorage`.

Migrated from a single 1.8k-line `index.html` (kept for reference in [`legacy/`](./legacy)) to a **Next.js 15 (App Router) + TypeScript** application, with every functional and UI bug from the review fixed.

## Tech stack

- **Next.js 15** (App Router) + **React 19** + **TypeScript**
- **Three.js** (npm, dynamically imported + code-split — no CDN/SRI risk) for the animated aura orb, with a CSS fallback on no-WebGL / reduced-motion
- **Web Audio API** — soundscapes synthesized live from filtered noise
- **Web Speech API** — voice input + read-aloud
- **Canvas 2D** — mood trend + soundscape visualizer
- **next/font** — Fraunces + Outfit self-hosted (removes the third-party Google Fonts request, reinforcing the privacy claims)
- **localStorage** — all persistence; the design system is preserved verbatim in `globals.css`

## Deploy (Netlify)

This is a full Next.js app, **not** a static site — the Groq chat needs a server-side
secret, so it runs as a serverless function. Netlify handles this out of the box; you
do **not** need a separate backend.

1. Connect the repo in Netlify → **New site from Git** (branch: `nextjs-migration`, or
   `main` once merged). `netlify.toml` already sets the build command, Node version,
   and the Next.js runtime plugin.
2. In **Site settings → Environment variables**, add:
   - `GROQ` = your Groq API key (from https://console.groq.com/keys)
   - *(optional)* `GROQ_MODEL` to override the default model
3. Deploy. The homepage is served as static assets; `/api/chat` runs as a Netlify
   Function. The key stays server-side and never reaches the browser.

> GitHub Pages can't run this app (it needs a build + functions). Netlify is the target.

## What changed from the single-file version

Bugs fixed during the migration:

- **Language now persists** across reloads (`aura_lang`) and drives the whole UI, not just ~8 strings. All copy is keyed through a proper i18n system with English fallback.
- **RTL is applied at the document level** (`<html dir>`) for Arabic/Urdu, not just the hero.
- **Today's mood selection + tip are restored on load** (previously the panel always looked unselected after a refresh).
- **Accessibility:** the mobile nav is `inert` when closed (no more tabbing into hidden links); the upgrade modal has a real focus trap, Escape/click-outside close, and restores focus on close.
- **Contrast:** the `--dim` token was lightened to meet WCAG AA on small text.
- **Metadata:** added a generated OG image, `summary_large_image` Twitter card, and a favicon.
- **Supply chain:** Three.js is an npm dependency (code-split), not a CDN `<script>`; fonts are self-hosted.

## Honest scope notes

- **Chat is powered by Groq (real LLM).** `src/app/api/chat/route.ts` calls the Groq API (default model `llama-3.3-70b-versatile`) with an Aura system prompt, replying in the user's selected language. The API key is read from the server-only `GROQ` env var and never reaches the browser. **Crisis messages are detected client-side and never sent to the model** — they instantly surface real helplines and always bypass the daily limit. If the API is unavailable, chat gracefully falls back to the local rule-based engine in `src/lib/chatEngine.ts`. Set your key in `.env` (see `.env.example`).
- **UI i18n is English-first.** The interface, navigation, hero, and greeting are localized into 6 languages; longer-form static prose falls back to English pending native-speaker review. Live chat replies, however, are generated by the model in whichever of the 6 languages is selected.
- **Pro upgrade is a demo** — it flips a local flag; no real payment processor. The modal says so.
- No accounts, no cross-device sync — clearing browser data wipes everything (a stated privacy feature).
